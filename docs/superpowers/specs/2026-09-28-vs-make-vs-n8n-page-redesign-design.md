# `/vs/make-vs-n8n` page redesign — design

## Goal

Make the comparison page feel less generic and AI-generated by anchoring it in a real workflow running on the user's own n8n instance. Differentiator: no other "Make vs n8n" page shows actual production data.

## Problem

Current page is structurally sound (TL;DR → table → per-criterion cards → when-to-use → FAQ → CTA) but visually generic:
- Pure text + tables. Zero product imagery.
- All cards use the same `rounded-2xl border bg-theme-5 p-6` template.
- Copy reads as templated ("TL;DR", "Criterion", "Winner") without personality.
- Visually indistinguishable from a Medium article or AI-generated comparison.

## Solution

Add one new section — **"Workflow reality check"** — between TL;DR and Comparison table. Show one real workflow from the user's n8n instance as an SVG diagram with inline annotations and hard numbers. Same brand palette, no new deps.

## Section structure

```
<section bg-primary class="section">
  eyebrow + heading + subtitle
  ─────────────────────────────────────
  ┌──────────────────┐  ┌─────────────┐
  │                  │  │ Callout 1   │  ← points to a specific node
  │  Workflow SVG    │  │ "este IF..." │
  │  (dark, n8n-style)│  ├─────────────┤
  │  nodes + edges   │  │ Callout 2   │
  │                  │  │ "$0.001/op"  │
  └──────────────────┘  ├─────────────┤
                        │ Callout 3   │
                        └─────────────┘

  stats row: 2,431 ejecuciones/mes · 14 hrs ahorradas/semana · $X costo/op
  caption: "Workflow real corriendo en producción"
</section>
```

Mobile: SVG stacks above callouts (or callouts as accordion).

## Visual treatment

- Section bg: `bg-primary` (cream `#FFFFFF` in Tailwind = white, theme-5 for cards).
- Diagram container: dark canvas `#1E1810` (theme-3, matches n8n canvas bg).
- Nodes: brand orange `#f96e03` accent for "interesting" nodes (IF branches, error handlers), gray for transit nodes.
- Edges: white-ish lines, with subtle curve (cubic bezier).
- Callout cards: white card on cream, with orange left-border.
- Annotations: 2-4px orange dots connected to the SVG node via leader line (SVG overlay or CSS positioning).

## Copy changes (3 spots, minimal)

1. **Hero subtitle** (en/es/pt) — replace generic phrasing with personal opener.
   - EN: "I've shipped enough on both to have opinions — here's what I'd actually pick in 2026."
   - ES: "He montado lo suficiente en ambos como para tener opinión — esto es lo que elegiría en 2026."
   - PT: same shape.

2. **TL;DR opener** (en/es/pt) — prepend a one-line "I use n8n for X, here's why":
   - EN: "I've shipped 30+ workflows on n8n since 2023 — and only 2 on Make. Here's why."
   - ES: "Llevo 30+ workflows en n8n desde 2023 — y solo 2 en Make. Por qué."
   - PT: similar.

3. **New section copy keys** in `dictionaries/*.json`:
   - `compare.makeVsN8n.workflowCheck.eyebrow` = "REALITY CHECK" / "REALIDAD" / "REALIDADE"
   - `compare.makeVsN8n.workflowCheck.heading` = "Este workflow corre en mi n8n ahora mismo" / equivalents
   - `compare.makeVsN8n.workflowCheck.subtitle` = one-sentence framing
   - `compare.makeVsN8n.workflowCheck.callouts[]` = 3 entries, each `{ label, stat, body }`
   - `compare.makeVsN8n.workflowCheck.stats[]` = 3 entries, each `{ value, unit, label }`
   - `compare.makeVsN8n.workflowCheck.caption` = "Workflow real en producción"

## Component structure

New file: `components/sections/workflow-canvas.tsx` (~120 lines)
- Props: `nodes` (array of `{id, label, x, y, kind: 'start'|'action'|'branch'|'end'}`), `edges` (array of `{from, to, label?}`), `callouts` (positioned annotations).
- Renders inline SVG with absolute-positioned callout cards.
- Pure server component (no interactivity needed for v1).
- Layout: SVG fills the left ~60%, callouts overlay on right ~40%. Mobile: stacked.

New helper: `lib/workflow-layout.ts` (~30 lines)
- Takes n8n workflow JSON, returns positions for nodes + edges.
- Strategy: simple grid layout by node index (don't try to replicate n8n's actual layout algorithm). Each node gets a slot in a horizontal flow with branches dropping down.

New page section in `app/[lang]/vs/make-vs-n8n/page.tsx`: insert between TL;DR and Comparison table.

## Data flow

```
n8n MCP list_workflows → pick one with branching topology
                       ↓
get_workflow(id) → JSON { nodes, connections, name, ... }
                       ↓
lib/workflow-layout.ts → { nodes: [{id, label, x, y, kind}], edges: [...] }
                       ↓
components/sections/workflow-canvas.tsx → renders SVG + callouts
                       ↓
page.tsx → embeds between TL;DR and Comparison table
```

Execution stats (for the stats row): n8n MCP doesn't expose per-workflow execution counts in the same call. Options:
- A) Skip stats row entirely. Cleaner, less data dependency.
- B) Use execution data via n8n MCP if available; otherwise manual placeholder + "Last 30 days" caveat.
- C) Skip and rely on the workflow diagram + callouts alone.

**Default to A.** Add stats row only if execution data is available cheaply.

## Cost numbers (for callouts)

Make.com pricing is public:
- $0.0006 per operation on Core ($9/mo)
- $0.0024 per operation on Pro ($16/mo)
- $0.008 per operation on Teams ($29/mo)

n8n self-hosted: infrastructure cost only (~$20-50/mo VPS for the user's likely scale).
n8n cloud: same per-operation model as Make.

We can compute rough per-workflow cost: `nodes × operations_per_run × executions × make_rate`. We pick conservative numbers and round to "~$0.002/op" — no need to be precise, just concrete.

## Out of scope

- Restructuring existing comparison table.
- Rewriting FAQ.
- Changing page-level SEO (canonical, meta) — keep as is.
- Adding new `/vs/*` pages — this only touches make-vs-n8n.
- A/B testing different layouts.
- Interactive elements (hover-to-highlight-node, click-to-expand). Pure static render for v1.

## Risks

1. **Workflow data might be boring** — if user's n8n has only 2-3 simple linear workflows, the "reality check" loses impact. → Fallback: ask user to pick a workflow name; if no good candidate, drop the section.
2. **SVG layout fragility** — manual node positioning might look weird for workflows with many nodes (>15). → Cap rendered nodes at 12; truncate others with "+N more".
3. **i18n** — 3 dictionaries need updates. Each callout = 3 strings × 3 locales = 9 strings to keep in sync. → One PR per locale to keep reviewable.
4. **Brand visual mismatch** — the dark canvas in a cream page might feel jarring. → Use a 1px orange border on the SVG container so it reads as intentional, not a flash-cut.
