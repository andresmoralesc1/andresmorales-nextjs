## 1. Infraestrutura Segura: Caddy HTTP/3, UFW e Fail2ban

Nossa abordagem de infraestrutura foca na simplicidade defensiva e no isolamento de serviços.

### Firewall UFW Estrito
Bloqueamos qualquer tráfego desnecessário, mantendo ativas apenas as portas essenciais:

```bash
# Política base: bloqueio estrito de entrada
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp comment 'SSH bastion'
sudo ufw allow 80/tcp comment 'HTTP ACME challenge'
sudo ufw allow 443/tcp comment 'HTTPS TLS 1.3'
sudo ufw allow 443/udp comment 'HTTP/3 QUIC'
sudo ufw enable
```

Com o **Fail2ban** ativo monitorando tentativas contra SSH e serviços autenticados, tentativas maliciosas são mitigadas instantaneamente.

### Caddy com HTTP/3 Nativo
O Caddy atua como proxy reverso com suporte nativo a HTTP/3 (QUIC via UDP) e TLS 1.3 automático:

```caddy
gatocolectivo.com {
    encode zstd gzip
    reverse_proxy 127.0.0.1:3000 {
        header_up Host {host}
        header_up X-Real-IP {remote_host}
    }
    header Strict-Transport-Security "max-age=31536000; includeSubDomains; preload"
    header X-Content-Type-Options "nosniff"
    header X-Frame-Options "DENY"
}
```

### Backups Automatizados no Telegram Vault
Para garantir cópias de segurança fora do servidor sem fricção, criamos uma rotina que envia os dumps compactados e criptografados diretamente para o Telegram via Bot API:

```bash
#!/usr/bin/env bash
set -euo pipefail
BACKUP_DATE=$(date +%Y%m%d_%H%M%S)
ARCHIVE="/tmp/db_snapshot_${BACKUP_DATE}.sql.gz"

# Dump e compressão
docker exec -t postgres_prod pg_dump -U postgres app_db | gzip -9 > "$ARCHIVE"

# Envio seguro ao Telegram
curl -s -F chat_id="${TELEGRAM_ADMIN_CHAT_ID}" \
     -F document=@"${ARCHIVE}" \
     -F caption="🛡️ Snapshot automatizado DB: ${BACKUP_DATE}" \
     "https://api.telegram.org/bot${TELEGRAM_BACKUP_BOT_TOKEN}/sendDocument"

rm -f "$ARCHIVE"
```
