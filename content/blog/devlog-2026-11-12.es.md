# Construir en Público: De la Experiencia Visual al Hardening en el Servidor

El desarrollo de software moderno no termina cuando el componente de React compila sin errores. La verdadera ingeniería ocurre cuando sincronizas la experiencia de usuario de alto impacto, pipelines de distribución multicanal automatizados y una infraestructura Linux en producción impenetrable.

Hoy en el estudio abordamos dos frentes simultáneos a través de nuestra arquitectura multi-repositorio: la expansión del motor de telemetría y distribución autónoma de contenidos en `andresmorales-nextjs`, junto a una optimización quirúrgica de rendimiento y micro-interacciones en la plataforma de ticketing `que-nivel-maribel`.

## 1. El Reto del Día: Automatización sin APIs Abusivas y Optimización Extrema

Nos encontramos con tres desafíos principales:
1. **Distribución multicanal desatendida**: Publicar actualizaciones técnicas en redes sociales sin depender de planes API con costes prohibitivos ni flujos manuales propensos al error humano.
2. **Performance y UX de eventos de alta concurrencia**: En la plataforma de ticketing, los activos de marca de alta resolución estaban penalizando el LCP (Largest Contentful Paint) y el viewport móvil sufría de zoom automático en inputs de iOS.
3. **Hardening y Resiliencia en VPS Linux**: Mantener un entorno de producción blindado con HTTP/3 nativo, mitigación proactiva de intrusiones y snapshots encriptados automáticos sin incurrir en infraestructuras sobrediseñadas.

## 2. Decisiones de Arquitectura y Automatización

### Pipeline Headless con Playwright y Publicador Directo
Implementamos un poster automatizado con Playwright headless para interactuar con interfaces web de forma segura, junto con un publicador directo sobre la API UGC v2 para LinkedIn con captura y refresco de tokens. Toda la generación ahora cuenta con un escáner multi-repositorio trilingüe y webhooks interactivos de despliegue conectados a Telegram.

### Rendimiento Frontend y Mobile First
En la plataforma de ticketing (`que-nivel-maribel`):
- **Eliminación del zoom en iOS**: Forzado de inputs a 16px mínimos y configuración de `viewportFit=cover` junto al meta `theme-color`.
- **Optimización de imágenes con Next.js Image**: Definición estricta de `sizes` y reducción de activos raw (reduciendo más de 212 KiB de carga innecesaria en el primer render).
- **Inversión dinámica de contraste**: Navbar con detección de scroll que permuta fondos y versiones del logotipo según el contenedor subyacente para garantizar legibilidad WCAG AAA.

## 3. Infraestructura, Hardening y Seguridad en Producción

La fiabilidad del servidor se sustenta en una configuración minimalista y robusta:

- **Firewall UFW Estricto**: Políticas predeterminadas en DROP para tráfico entrante, permitiendo exclusivamente los puertos 22 (SSH con llave ed25519), 80 (HTTP) y 443 (HTTPS/QUIC).
- **Fail2ban**: Jails activas para mitigar ataques de fuerza bruta en `sshd` y autenticación de contenedores Docker.
- **Caddy Server con HTTP/3**: Terminación TLS 1.3 automática, compresión zstd y negociación de protocolo QUIC sin intermediarios pesados.
- **Backups Automatizados a Telegram Vault**: Scripts cron que generan volcados cifrados de la base de datos y los transmiten directamente mediante la API de Telegram a un canal privado de bóveda.

```bash
# Verificación de telemetría de red y firewall UFW
sudo ufw status verbose
# Status: active
# Logging: on (low)
# Default: deny (incoming), allow (outgoing), disabled (routed)
# To                         Action      From
# --                         ------      ----
# 22/tcp                     ALLOW IN    Anywhere
# 80/tcp                     ALLOW IN    Anywhere
# 443/tcp                    ALLOW IN    Anywhere
# 443/udp (QUIC HTTP/3)      ALLOW IN    Anywhere
```

Fragmento del pipeline de snapshot y réplica a Telegram:

```bash
#!/usr/bin/env bash
set -euo pipefail

TIMESTAMP=$(date +"%Y%m%d_%H%M%S")
BACKUP_FILE="/var/backups/db_${TIMESTAMP}.sql.gz.enc"

# Dump, compresión y cifrado simétrico con OpenSSL
docker exec -t postgres_prod pg_dump -U "$DB_USER" "$DB_NAME" \
  | gzip -9 \
  | openssl enc -aes-256-cbc -salt -pbkdf2 -pass env:BACKUP_PASSPHRASE -out "$BACKUP_FILE"

# Transmisión inmediata a la bóveda privada en Telegram
curl -s -F chat_id="$TELEGRAM_VAULT_CHAT_ID" \
     -F document=@"$BACKUP_FILE" \
     -F caption="📦 Backup de Producción verificado: ${TIMESTAMP}" \
     "https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/sendDocument"

rm -f "$BACKUP_FILE"
```

## 5. Lecciones Aprendidas

1. **Las APIs oficiales no siempre son la única respuesta**: Cuando los costes de integración amenazan la viabilidad de la automatización interna, Playwright bien orquestado en modo headless proporciona una alternativa confiable y resiliente.
2. **Los detalles en móvil definen la conversión**: Un input con fuente menor a 16px arruina la experiencia en Safari iOS con zooms accidentales; corregirlo es una prioridad innegociable de UX.
3. **La infraestructura debe ser simple y observable**: Menos capas es más seguridad. Caddy y UFW bien configurados superan la sobrecarga de soluciones complejas cuando se gestionan con disciplina.
