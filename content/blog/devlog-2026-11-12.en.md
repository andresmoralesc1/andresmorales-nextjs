## 3. Server Hardening & DevOps in Production

Reliability is rooted in simplicity and strict defaults:

- **UFW Firewall**: Default DROP policy on incoming connections, strictly exposing ports 22, 80, and 443 (TCP & UDP for QUIC).
- **Fail2ban Jails**: Real-time brute force protection on `sshd` and authentication endpoints.
- **Caddy Reverse Proxy**: Native HTTP/3 (QUIC) and automated zero-touch TLS 1.3 certificates.
- **Encrypted Telegram Vault Backups**: Automated cron snapshots encrypted via OpenSSL and streamed directly into a private Telegram storage vault.

```bash
# Production firewall verification
sudo ufw status verbose
# Status: active
# Logging: on (low)
# Default: deny (incoming), allow (outgoing), disabled (routed)
# To                         Action      From
# --                         ------      ----
# 22/tcp                     ALLOW IN    Anywhere
# 80/tcp                     ALLOW IN    Anywhere
# 443/tcp                    ALLOW IN    Anywhere
# 443/udp (QUIC HTTP/3)      ALLOW IN    Anywhere
```

Automated encrypted database replication to Telegram:

```bash
#!/usr/bin/env bash
set -euo pipefail

TIMESTAMP=$(date +"%Y%m%d_%H%M%S")
BACKUP_FILE="/var/backups/db_${TIMESTAMP}.sql.gz.enc"

# Dump, compress, and AES-256 encrypt
docker exec -t postgres_prod pg_dump -U "$DB_USER" "$DB_NAME" \
  | gzip -9 \
  | openssl enc -aes-256-cbc -salt -pbkdf2 -pass env:BACKUP_PASSPHRASE -out "$BACKUP_FILE"

# Stream directly into private Telegram vault
curl -s -F chat_id="$TELEGRAM_VAULT_CHAT_ID" \
     -F document=@"$BACKUP_FILE" \
     -F caption="📦 Production Snapshot Verified: ${TIMESTAMP}" \
     "https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/sendDocument"

rm -f "$BACKUP_FILE"
```
